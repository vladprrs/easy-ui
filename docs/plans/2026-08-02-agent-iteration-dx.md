# Agent-iteration DX (harness-DX v3): меньше итераций на компонент при пересборке DS из Figma

Дата: 2026-08-02. Статус: **draft, ждёт адверсариального ревью (Stage 2)**.

## 1. Диагноз: на чём агент теряет время

Замер по проду (`yandex-pay-v2`, агент yp-figma-rebuild, 2026-08-01 18:27 → 2026-08-02 10:52, ~16,5 ч):

| Метрика | Значение |
| --- | --- |
| Опубликовано атомов | 13 (`pay-*`) |
| Ревизий компонентов | 35 (в среднем 2,7; `pay-box` — 8, `pay-button-group` — 6) |
| Ревизий `ypv2-probe-atoms` | **40** (док 124 КБ, 16 экранов) + `ypv2-probe-molecules` — 7 |
| Версий темы | **13** |
| Итого записей на сервер | ~95 ≈ **7 записей на принятый атом** |

Разбор диффов ревизий (`pay-button-group` 1→6, `pay-box` 1→8) показывает четыре системных источника лишних итераций:

### 1.1 Церемония «пере-сохрани probe» (стоимость: ~40 публикаций 124-КБ дока)
Ревизия прототипа пинует manifest-hash компонентов и `designSystemMetaVersion`. После **каждой** публикации компонента и каждого PATCH темы агент обязан пересохранить probe-прототип до снапа, иначе snap показывает старое. 40 ревизий probe против 35 ревизий компонентов — почти 1:1: подавляющая часть — чистая церемония, не контент. Забытый шаг даёт «фикс не сработал»: в истории есть **точный no-op** (`pay-button-group` rev 2→3 идентичны) — агент перепубликовал код, потому что снап не изменился.

### 1.2 Нет покомпонентного рендера — приёмка атома требует прототип
Единственный способ увидеть атом — экран в probe-прототипе с канвасом, точно равным размеру Figma-фрейма (`compare.mjs` падает exit 3 при несовпадении размеров). Отсюда сам гигантский probe-док, его рост и его пересохранения.

### 1.3 Слепой пиксельный дифф → серии 1-px итераций
Обратная связь — только «N px differ = X%» и красный diff-PNG. Агент угадывает правку: `gap: 2→4`, `position: top 1px`, зажим высоты `24px` — по 2–3 итерации на компонент там, где числовое сравнение геометрии (gap/размеры боксов против выписки из Figma) дало бы ответ за одну. Geometry-probe в продукте уже есть, но не сравнивает с эталоном и не работает без прототипа.

### 1.4 Churn темы: 13 версий × каскад пересохранений
Каждая правка темы = полный словарь токенов + пересохранение всех probe до пере-снапа. Плюс известная мина: нарушение правил `space.*` **молча** откатывает шкалу на каноническую.

### 1.5 Длинный цикл «посмотреть один фикс»
5 команд на взгляд: publish → re-save probe → snap enqueue → poll/download → локальный pixelmatch.

## 2. Что меняем в продукте

Приоритет по соотношению «убитые итерации / стоимость».

### P1 (blocker DX) — Покомпонентный preview-рендер
`POST /api/design-systems/:ds/components/:id/preview` `{props?, slots?, viewport?, theme?, dsf?}` → PNG. Рендер **всегда head-ревизии** компонента и **текущей** темы, размер PNG = content-box (hug), либо заданный viewport. Реализация — поверх существующего screenshot-pipeline (`server/screenshot/`), обёртка-стенд вместо прототипа. Driver: `driver.mjs preview <componentId> [props.json] [--dsf 2] [--viewport WxH] [--theme …]`.
- Убивает: церемонию probe для приёмки атомов (§1.1, §1.2) и проблему «канвас = размер фрейма» — PNG сам по себе content-sized.

### P2 — Head-tracking прототипы
Флаг документа `"track": "head"` (для probe/dev-доков): рендер и snap такого прототипа всегда используют последние ревизии компонентов и последнюю версию темы, без пере-сохранения. Обычные прототипы остаются запинованными (прод-семантика не меняется).
- Убивает: оставшиеся пересохранения probe-доков для molecule/organism-экранов, где преview одного компонента недостаточно.

### P3 — Встроенный дифф с эталоном + кластеры расхождений
`driver.mjs preview … --ref figma@2x.png [--threshold N]` (и то же для `snap`): сервер или driver считает pixelmatch сам и возвращает `% mismatch`, diff-PNG и **bounding-box'ы кластеров** расхождений в px («кластер 12×3 px @ (208, 41)»). При несовпадении размеров — не exit 3, а отчёт «candidate 328×56 vs ref 328×58» (это уже сам по себе диагноз).
- Убивает: половину слепых 1-px итераций (§1.3), локальную возню с pixelmatch.

### P4 — Числовая приёмка геометрии против выписки из Figma
Расширить geometry-probe на preview (`driver.mjs preview … --geometry` → боксы узлов) и добавить `driver.mjs expect <expected.json> <actual.json>`: сравнение размеров/gap/паддингов с допуском, вывод в стиле «gap expected 8, got 6». `expected.json` агент пишет прямо из выписки Figma (§4.1 скилла).
- Убивает: оставшиеся угадывания px (§1.3) — числовой вердикт до пиксельного.

### P5 — Защита от no-op и видимость staleness
1. Publish компонента с кодом, идентичным head (нормализованное сравнение), → ответ `unchanged: true, rev N` без новой ревизии; driver печатает «identical to rev N — nothing to publish».
2. `snap`/`preview` в выводе печатают, **что именно отрендерено**: ревизии компонентов и версию темы. Стало старое — видно мгновенно, а не через «фикс не сработал».

### P6 — Тема: dry-run и конец молчаливого отката
1. `api.mjs theme --dry-run`: валидация + дифф токенов + итоговая `resolvedSpaceScale` без записи.
2. Нарушение правил `space.*` → **422 с объяснением** вместо молчаливого фолбэка (микромиграция: на существующих темах фолбэк уже не активен — прод-шкалы валидны; проверить аудитом перед включением).
3. Ответ PATCH темы перечисляет прототипы с устаревшими пинами (с P2 для probe-доков список пуст).

### P7 — Синк скилла `yp-figma-rebuild`
Переписать цикл приёмки (§4–5 скилла) на preview-based: атом принимается через `preview --ref --geometry`, probe-прототипы нужны только со стадии молекул/экранов и объявляются `"track": "head"`. Пересобрать `share/yp-figma-rebuild-skill` + `.tgz`, продублировать в `.claude/skills/yandex-pay` при пересечении.

## 3. Ожидаемый эффект

Цикл «правка → вердикт» сжимается с 5 команд до 1–2 (`component` → `preview --ref --geometry`); записи на атом ~7 → ~2–3; исчезают классы ошибок «stale pin» и «canvas size mismatch»; пиксельные подгонки получают числовую наводку вместо угадывания.
