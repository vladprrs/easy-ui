# Экран компонентов: витрина вместо списка (макет 06)

Дата: 2026-07-31. Источник: claude.ai/design `20dd217d-bd95-4eb8-823f-f799d0102a5e`
(«Easy-UI Redesign»), раздел **06 Библиотека** в `design_handoff_easyui_redesign/README.md`.
Сам `Easy-UI Redesign.dc.html` по-прежнему не читается через `DesignSync get_file` — лимит
256 KiB съедают встроенные шрифты, разметка за отсечкой (см. память `pay-brand-redesign-2026-07-30`).

## Что было не так

`/library` после брендовой волны 2026-07-30 получил цвета Пэй, но остался прежним по смыслу:
левая колонка-навигатор со списком имён по уровням Atomic Design + правая панель-досье
выбранного компонента. Проблемы для пользователя:

1. **Экран не отвечает на свой вопрос.** Чтобы понять, «что тут есть», приходилось кликать
   по именам по одному: превью показывалось только для выделенного компонента.
2. **Двойная деталь.** Панель `ComponentMetadata` дублировала страницу компонента
   (`/library/c/:id`), где то же самое есть подробнее и с контролами props.
3. **Скрытый вход.** Дизайн-система выбиралась чипом в сайдбаре, дефолт — «первая по алфавиту»;
   компонентов других систем на экране просто не было видно.
4. **Фильтры-тумблеры статусов** допускали пустое пересечение и не имели состояния «любой».
5. Формально главное действие («опубликовать компонент») отсутствовало: публикация — только API,
   а подсказка про неё пряталась в пустом состоянии.

## Что делаем (макет 06)

- Хиро-панель: заголовок дисплейной гарнитурой 56 («живых» — единственный акцент, курсив + красный),
  подзаголовок со счётчиками и объяснением, зачем экран; primary «Опубликовать компонент».
- Тулбар на канве: сегмент «Компоненты · Композиции», поиск-пилюля, чипы систем (с числом
  компонентов, по умолчанию «Все системы»), чипы статуса с одиночным выбором и «Любой статус».
- Грид карточек 3×N, сгруппированный по уровням Atomic Design; при поиске — одна секция
  «Нашлось N» в порядке ранга (существующий `searchComponents`).
- Карточка: превью-зона 170px на лаванде с **живым** превью (`/capture/component/...` в iframe,
  монтируется по IntersectionObserver), имя 16/500, описание, чипы версии/уровня/системы,
  строка статуса (точка #23E13F «готов» / #C6B1FD «черновик») и использования. Вся карточка —
  ссылка на страницу компонента; конкурирующих кнопок внутри нет.
- Состояния (макет 07): скелетоны, ошибка, пустая библиотека с брендовыми кругами,
  «ничего не нашлось» со сбросом фильтров. Диалог публикации (макет 08) вместо кнопки в никуда.
- Раздел «Композиции» переведён на брендовые пресеты, чтобы обе вкладки читались как один экран.

## Решения и осознанные потери

- Досье компонента больше не дублируется на витрине: параметры, исходник и граф использования
  живут на `/library/c/:id`. На карточке остаётся ровно то, по чему компонент выбирают.
- «Похожие компоненты» (`similarComponents`) с экрана ушли: место им — на странице компонента,
  отдельной задачей. Хелпер и его тесты сохранены.
- Статусы и Figma по-прежнему грузятся best-effort после манифеста (N запросов `GET /api/components/:id`
  на область показа) — карточка рисуется и без них, поэтому первый пейнт не блокируется.
